# SOP workshop

These files are **drafts**, not instructions to the AI. The assistant currently reads only `src/server/assistant/TEAM_SOP.md`, which still says there are no approved rules. Move a concise, Head-approved version into that file only after reviewing it together and testing the answers in Preview.

Discuss one repeatable process at a time. Prefer a process that happens often, crosses roles, or causes expensive delays. A useful SOP answers:

1. **Purpose and success:** What output is needed, and what proves it worked?
2. **Trigger and owner:** When does the process start, who is accountable, and who participates?
3. **Required input:** What must be ready before work starts? Which links or briefs are optional?
4. **Steps and handoffs:** What is produced at each step, who reviews it, and who opens the next task?
5. **Timing:** Which deadlines are fixed, which are proposed by the next owner, and what happens when time is insufficient?
6. **Definition of done:** What evidence or link must be attached before approval?
7. **Exceptions:** What to do when material, approval, a participant, or a location is unavailable.
8. **Template mapping:** Which steps become separate tasks, which become optional checkpoints, and which belong only in the written SOP?

Avoid turning every sentence into a checkbox. Keep the task form short. The AI may suggest optional checkpoints based on an approved SOP, but any write still needs the user's explicit confirmation and current task permissions.

Today the assistant reads only the first 20,000 characters of the single approved Markdown file. It can already propose **one explicitly named checkpoint** for confirmation; it does not yet select an SOP and generate a full checkpoint plan from it. Once several SOPs are approved, select the relevant version for the task instead of stuffing every detailed SOP into one prompt. This is knowledge supplied at answer time, not model fine-tuning.
